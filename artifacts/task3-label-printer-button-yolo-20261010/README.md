## 小按钮识别流程

原图中的按钮通常只有约 6～10 像素宽，因此运行 `recognize.py` 的流程是：

1. 完整画面预测打印机和按钮，使用类别独立的 NMS，不让打印机框压掉里面的按钮框。
2. 在置信度至少 0.1 的预测打印机周围取正方形局部图，边长为打印机最长边的 1.8 倍且至少 160 像素；同一个模型再次识别按钮。
3. 局部图按钮坐标映射回原图，按类别阈值及父打印机阈值过滤。局部图外仍保留完整图检测到的按钮。最多处理 10 个打印机候选；不假定工位固定坐标。

打印机局部图内使用局部识别结果，不混入同一目标的完整图按钮框；跨局部图的重复检测再按同类 IoU 去重。不会强制输出恰好两个按钮，也不会给漏检按钮编造位置。

**只运行普通 YOLO 单次全图推理不等于本包的完整识别流程。** 需要使用这里的 `Detector` / `recognize.py` 才会启用按钮局部细化。

## 使用

从仓库根目录进入本模型目录，使用已安装依赖的 Python 环境（本次验证为 Python 3.12；版本记录见 `requirements.txt`）：

```bash
cd artifacts/task3-label-printer-button-yolo-20261010
python recognize.py \
  /完整路径/待识别图片.jpg \
  --output /tmp/task3-preview.jpg \
  --json-output /tmp/task3-result.json
```

新环境可先执行 `python -m pip install -r requirements.txt`。本机原训练环境路径为 `/home/vnv/.venvs/cup-dispenser-export-20260922/bin/python`，其他电脑不需要具有这个路径。不要把已画检测框的预览图作为正式识别输入。

默认使用 `weights/best.pt` 和 `runtime-config.json` 中按类别校准的阈值。指定 `--weights weights/best.onnx` 可切换 ONNX；两种权重都与配置内 SHA256 绑定，防止模型混用。手动试验阈值时同时提供 `--printer-conf`、`--button-conf`，不要直接沿用杯子模型的阈值。

Python 接口：

```python
import cv2
from recognize import Detector

detector = Detector()
result = detector.predict(cv2.imread('/完整路径/图片.jpg'))
for button in result.get('objects', {}).get('button', []):
    print(button['bbox_xyxy_px'], button['center_uv'], button['confidence'])
```

输入是 BGR uint8 原始彩色图；输出所有实例的原图像素框与中心。每个按钮的 `method` 说明来源是完整图还是预测打印机局部图，局部结果另有父打印机置信度。

两个按钮都标为 `button`，**没有区分各自功能**。框中心不保证是物理按钮几何中心；不输出机器人坐标、按压位姿或自动选按钮，`robot_motion_ready` 始终为 false。摄像机标定和按压控制不在本模型内。

## 验证与复现

- `checkpoint-selection.json`：仅在训练原图选择阈值，再根据 6 张完整验证原图的端到端表现选择 best/last 权重；测试不参与选择。
- `verification.json`：完整原图的训练/验证/测试分项、54 张测试合成变体、9 张移除目标的合成负样本。每个按钮单独匹配，类别一致且 IoU ≥ 0.5 才算正确。另有单次完整图推理诊断对照。
- `replay.json`：逐图预测、失败原因与匹配记录。
- `prediction-sheet-1.jpg` 至 `prediction-sheet-3.jpg`：统一完整画面尺寸的结果总览。`prediction-detail-*.jpg` 仅是观察细节的放大预览，不是推理输入。
- `onnx-parity.json`：60 张原图上 PT 与 ONNX 完整流程对照。
- `real-negative-verification.json`：另外 20 张封盖杯桌面图片上的无目标检查。已逐图确认没有本次目标打印机及其按钮；这些图片属于同一个额外场景，未参与训练或阈值选择。
- `test_runtime.py`：坐标变换、相邻按钮保留、类别独立去重、错误模型/阈值拒绝等单元测试。

训练器指标混合了完整验证图和人工框裁图，**不能当作实际整幅画面的识别率**；以 `verification.json` 的端到端结果为准。数据集中只有同一台设备，许多视角相似，9 张测试样本也很少；不能据此保证换设备、剧烈换角度或现场识别准确率。合成负样本不替代真实无目标场景。

本机复现脚本顺序：`prepare.py`、`train.py`、`select_checkpoint.py`、`export_model.py`、`verify_model.py`、`verify_export.py`、`verify_negatives.py`、`python -m unittest -v test_runtime.py`。准备脚本为保护数据会拒绝覆盖现有 dataset；需在新目录且保证人工标签、原图、通用初始权重路径有效时运行。权重/报告包若单独复制，不代表附带了原始训练图片或通用初始权重，不能仅凭权重包完整重训。

本目录为 GitHub 发布包，含识别代码、权重、配置、验证报告和少量结果预览，不含原始训练图片、标注 ZIP 或通用 COCO 初始权重。训练/评估脚本中的 `/home/vnv/...` 路径用于记录原训练环境；在其他电脑重训或重跑数据验证前，需准备原始数据并修改这些路径。直接使用已训练模型推理不依赖那些数据路径。
